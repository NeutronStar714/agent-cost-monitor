![agent-cost-monitor](assets/header.svg)

在 AI 编程助手本来就有的界面上，实时显示花费与「燃烧速率」。

[English](README.md) · **简体中文**

- **Claude Code CLI**：状态栏一行，原地重绘。
- **其他情况**——Codex、DSH，或者想在 Claude Code 里看到图而不只是一个数字——用 **Tauri 悬浮窗**：
  同样的一组数字，外加一张燃烧速率曲线。
- **`acm tray`**：在 Windows 通知区域放一个数字，把本回合花费**画进图标本身**，菜单里有上一个
  已完成的回合、会话累计和两个燃烧速率。助手在跑的时候它自己出现，安静五分钟后自己收起。
  `acm tray --install` 可以让它随登录启动。

状态栏是本项目唯一「只有一行」的形态，而且**仅限 Claude Code CLI**：

```
¥0.53 / ¥19.72 · β(t) ¥0.00/h · β ¥5.94/h · 5:21
```

## 数字的含义，以及 β 是什么

**β 是燃烧速率**，即每小时花掉多少钱。它是速率，不是累计值——回答的是「现在这个速度有多贵」，
而这正是助手跑起来以后最要紧的问题。

状态栏、悬浮窗和托盘菜单里都是这几个：

|||
|---|---|
| `¥0.53` | **本回合**——当前回合到目前为止的花费 |
| `¥19.72` | **本会话**——这次对话里所有回合的合计 |
| `β(t)` | **实时燃烧速率**——最近 `burnWindowMs`（默认 15 秒）的花费折算成每小时。没有花费时归零；它是滑动窗口，早先的调用滑出去之后自然下降 |
| `β` | **平均燃烧速率**——本回合花费除以本回合自己的时长 |
| `5:21` | **本回合已用时间**——回合一结束就停住 |

具体来说：所有数字都由宿主记录的 token 用量算出——输入、输出，以及分开统计的缓存读取/写入——
按每百万 token 对照取回的价目表计价，DeepSeek 的高峰/低谷时段照算，美元按欧洲央行每日参考汇率
换成人民币。没有任何数字来自墙钟时间的测量或估算；未定价的模型贡献为零，而不是给一个猜测值。

**如果用到的模型不在价目表里——或者网络根本取不到表——就自己给价格**，写在
`~/.agent-cost-monitor.pricing.json` 里，单位是「美元 / 百万 token」：

```json
{ "models": { "gpt-6-sol": { "input": 1.25, "cachedInput": 0.125, "output": 10 } } }
```

你列出的名字以这里的价格为准，而且每次取表之后都会重新套用（一次成功的取表不该丢掉本机唯一
能有的价格）。这些价格**故意不放在缓存目录**：`acm uninstall` 可能清掉缓存，而你自己敲进去的
价目表不该被我们删掉。缺少 `output` 价格的行会被跳过，而不是「能算一半就先算一半」——把输出
token 按零计价，会让一个回合看起来有价，实际被严重低估。

价目表同时**离线**留档在 `~/.cache/spend-watch/`：一份机器可读的记录
（`pricing-rows.json`）和一份人可读的文档（`pricing.md`），列出每个模型的价格、取表时间，以及
上一次**变动**的时间。只有取回的列表确实不同才会重写文档，所以价格变化看得见，而不会被悄悄抹平。
用 `acm pricing` 查看，用 `acm pricing --refresh` 重新取。

## 安装

```bash
npm install -g agent-cost-monitor     # 把 `acm` 放进 PATH
acm install                           # Claude Code 状态栏、/acm、配置文件
acm hook on                           # 会话开始时启动悬浮窗
acm tray --install                    # 通知区域那个数字，随登录启动（Windows）
```

需要 Node 20+（Codex 的 SQLite 交叉校验需要 22.5+）。悬浮窗和托盘目前**仅限 Windows**；
状态栏、守护进程和 CLI 是纯 Node，到处都能跑。

## 启动悬浮窗

```bash
acm launch                 # 复用已开的窗口，没有就开一个
acm launch --new           # 有意再开一个
acm launch --host codex    # 读 Codex，并在界面上说明
```

**Claude Code 只给状态栏，不给窗口。** 它的 CLI 和桌面版共用同一份配置文件，钩子没法只对桌面版
生效；而且一个和状态栏显示同样数字的窗口只是噪音。因此 `acm hook on` 会**移除**早期版本装上的
Claude Code 窗口钩子；确实想要桌面版那种情况，只能显式写
`acm hook on --host claude --window`。

`acm hook on` 给 **Codex** 装 `SessionStart` **和** `UserPromptSubmit` 两个钩子，所以窗口是
你开始干活时出现，而不是等你想起它才出现。Codex 可能会让你信任这个钩子一次——它保存每个钩子的
信任哈希，谁也伪造不了。

**回合计时从回合开始，到回合结束。** 宿主自己报了时长的（Codex 在任务完成时给
`duration_ms`），就**精确**采用那个数：一个跑了 1 分 52 秒的任务会停在 `1:52`，哪怕这行字是稍后
才画出来的。宿主什么都不报的（Claude Code），就在回合明显安静下来之后，取这个回合最后一个有记录
的步骤：先短暂延迟，然后给出正确的固定值。活儿停了之后，它绝不再往上爬。

## 通知区域里的那个数字

`acm tray` 把一个数字放在你本来就会看的地方——时钟旁边——而不是放在一个还得去找的窗口里。

- **图标就是数字**：本回合花费，最多三个字形（`.53`、`1.2`、`12`），由文字轮廓生成，并按系统
  实际给的方框缩放填满——200% 缩放下是 32 个物理像素。深色任务栏上白字，浅色任务栏上黑字，
  实时燃烧速率超过 `warnPerHour` 时变**琥珀色**。
- **菜单**放装不下的东西：上一个**已完成**的回合、会话累计、两个燃烧速率、宿主与模型、价目表
  状态，以及打开窗口和退出的入口。
- **有话可说的时候它才出现**——回合在跑，或者窗口开着——安静五分钟后自己隐藏。它不是常驻摆设。
- **`acm tray --install`** 写入登录项，**`acm tray --status`** 查看是否在跑，
  **`acm tray --stop`** 结束它；只写 `acm tray` 就是现在启动。

它是通过**任务计划程序**启动的，而不是作为这条命令的子进程：那样起的进程会在命令退出时被杀掉，
表现出来就是图标闪一下就没了。在任务栏自己的设置里，它显示为 **Windows PowerShell**，因为图标
属于真正持有它的进程，而不属于本项目。

## 设置告警阈值

所有界面共用同一个数字——窗口里的虚线、那个圆点，以及托盘的图标：

```bash
acm warn          # 查看
acm warn 8        # 设置，单位是数字所用的货币、每小时
```

它存在配置文件的 `warnPerHour` 里，改动前会留一份带时间戳的备份；守护进程会察觉文件变化，在下一次
轮询时生效，不需要重启任何东西。DSH 会话另有 dsh-budget-watcher 插件自己的阈值，管的是插件自己的
面板；**ACM 画出来的数字永远以 ACM 的阈值为准**，不管数据来自哪里——所以在这里设置，这里就一定变。

## 用 DSH 桌面版？先看这个

如果你的助手是 **DSH**，请从
[dsh-budget-watcher](https://github.com/NeutronStar714/dsh-budget-watcher) 开始：那是一个 DSH
宿主插件，带浮动面板、设置表单，以及针对 DSH 自身会话模型做的成本核算。

**本项目是它的下一步——跨平台。** 这里的计价引擎就是从那个插件里抽出来的，现在它能读每个宿主
写在磁盘上的东西，于是同一组数字可以跟到 Claude Code 和 Codex。两个都用的话就两个都装：它们的
配置方式一致（`burnWindowMs` 在两边含义相同），互不干扰。

## 工作原理

| 数据源 | 读什么 |
|---|---|
| **Claude Code** | `~/.claude/projects/**/*.jsonl` 会话记录 |
| **Codex** | `~/.codex/sessions/**/rollout-*.jsonl` 取每次调用的用量；rollout 里没有总数时，用 `state_5.sqlite` |
| **DSH** | dsh-budget-watcher 插件的 HTTP 路由——唯一还知道余额的数据源，而余额本项目故意不用 |

所有数字只作展示；每个渲染器都走同一个计价引擎。回合边界优先采用宿主自己记录的——Codex 的
`task_started`/`task_complete`、Claude Code 的提示词条目——只有在宿主什么都没记的时候，才退回到
用量样本。

## 命令

| | |
|---|---|
| `acm install [--host claude\|dsh\|all]` | 配置某个宿主（默认 Claude Code） |
| `acm hook on\|off\|status [--host claude\|codex\|all]` | 会话启动钩子 |
| `acm launch [--host h] [--new] [--quiet]` | 启动悬浮窗 |
| `acm tray [--install\|--uninstall\|--status\|--stop]` | 通知区域那个数字 |
| `acm warn [rate]` | 查看或设置数字变琥珀色的燃烧速率 |
| `acm pricing [--refresh]` | 离线价目表：里面有什么、什么时候变的 |
| `acm status` / `acm doctor` / `acm log [--lines N]` | 检测到什么、哪里坏了、发生过什么 |
| `acm uninstall [--self] [--keep-cache]` | 移除 acm 添加的一切 |
| `acm clean-profiles` | 清掉旧版本可能留下的 shell 垫片代码块 |

`--dry-run` 只打印计划，不做任何改动。

## 配置

`~/.agent-cost-monitor.json`，每个键都可以用环境变量覆盖：

| 键 | 默认值 | 含义 | 环境变量 |
|---|---|---|---|
| `backend` | `browser` | `browser` 用浏览器窗口，`tauri` 用悬浮窗 | `ACM_WINDOW_BACKEND` |
| `windowWidth` / `windowHeight` | `225` / `300` | 窗口尺寸（像素） | `ACM_WINDOW_WIDTH/_HEIGHT` |
| `windowX` / `windowY` | `40` / `80` | 打开位置 | `ACM_WINDOW_X/_Y` |
| `alwaysOnTop` | `true` | 保持在其它窗口之上 | `ACM_ALWAYS_ON_TOP=0` |
| `warnPerHour` | `15` | 曲线虚线所在位置、圆点变琥珀色的速率，也是托盘图标变琥珀色的速率 | `ACM_WARN_PER_HOUR` |
| `burnWindowMs` | `15000` | `β(t)` 的统计窗口 | `ACM_BURN_WINDOW_MS` |
| `pollMs` | `1000` | 窗口多久取一次数字 | `ACM_POLL_MS` |

`SPEND_WATCH_CURRENCY=USD` 改用美元计价。窗口会把自己放回最前，并修复被隐藏或最小化的窗口，但
**绝不会移动你自己摆好的窗口**，不论启动时给了什么参数。默认复用：已经开着的窗口原地不动，只有
`acm launch --new` 才会开第二个。

## 已知限制

1. **所有花费算在一起。** 子代理的消耗包含在内并有标记，但状态栏不按代理拆分。
2. **Claude Code 的回合边界是推导出来的**（依据提示词条目）；被压缩或继续过的会话，最早的几个
   回合可能归错。
3. **平均燃烧速率是本回合的**，配的是本回合自己的时钟，不是会话平均值。
4. **同一次 API 响应只计一次费**（按 `message.id`）；如果某个代理逐内容块记日志且不带 id，就会
   按行重复计数。
5. **首次运行时只有 DeepSeek 有价**，要等第一次取回价目表。未定价的模型读作零，而不是它的真实
   花费。
6. **`lib/` 是从 dsh-budget-watcher 0.7.2 复制过来的，不是共享的。** 两边有意各自演进；在一处
   修的 bug，应当去另一处核对。
7. **悬浮窗仅限 Windows。** 定位用的是 Win32 调用。状态栏、守护进程、CLI 和 Codex 适配器是纯
   Node、可移植；窗口要跨平台得加 `/Applications` 的浏览器路径、定位的平台分支，以及
   `.app`/`.dmg` 打包目标。
8. **窗口页面是单个 HTML 文件、内联 JavaScript。** 测试会针对桩 DOM 执行那段脚本，所以逻辑和
   作用域错误能抓到；布局、CSS 和渲染抓不到——那些仍然要用眼睛看。
9. **钩子只在 Codex 上验证过，没在 Claude Code 桌面版上验证**，因为构建这个项目的机器上没有
   Claude Code 桌面版。改配置文件的部分有测试；真正触发没有。
10. **复用的窗口保持它创建时的宿主。** 想绑另一个宿主就关掉重开。为复用加上宿主感知还不值得。
11. **浏览器窗口无法一出现就是正确尺寸**，而且在 200% 这样的高缩放下，它的任务栏图标会被
    Windows 放大、显得发虚——Edge 自带的默认地球图标同样发虚，这是「不是图的问题」最快的证明。
    `backend: "tauri"` 两个问题都避开：悬浮窗自己声明尺寸，并带一个真正的窗口图标，按 **128 px**
    构建，于是 200% 缩放下 64 px 的任务栏槽位正好是 2:1 缩小。窗口图标是编译进去的，改它要重新
    构建悬浮窗；而系统的图标缓存可能继续按同一个 exe 路径画旧位图——重启资源管理器可以清掉。
    悬浮窗如果没能出现，它自己的说明会写进窗口日志（`acm log`）而不是被丢掉；接着浏览器兜底会跑，
    那种兜底是唯一无法避免图标发虚的情况。
12. **余额故意不显示。** 它是 DeepSeek 的，而且只有 DSH 读得到；在一个同时服务 Codex 和
    Claude Code 的窗口里，它描述的是另一家服务商。
13. **不处理阶梯计价。** 取回的 459 条里有 80 条在某个 token 阈值之上给出第二档价格
    （`overrides[]`，例如提示词超过 272k token 后翻倍）。这些档次被忽略，所以超长上下文的调用会被
    低估；整次调用都按第一档计价。
14. **有些条目在源数据里就是零价**——459 条里有 19 条，几乎都是 `:free` 变体——所以零不一定
    代表缺价。你用的模型读作零而服务商确实收费，就自己给价格（见上文）；读作零且确实免费，就别管
    它。绝不能发生的是：用零冒充「不知道」——所以未定价的模型显示 `(no rate card)`，而不是
    `¥0.00`。
15. **价目表来自 `openrouter.ai`，没有它就只有 DeepSeek 能计价。** 该主机不可达时（有些网络会
    超时），内置的 DeepSeek 表仍然能给 DeepSeek 计价，其它模型一律读作未定价，并且状态栏会说明
    这一点（`(no rate card)`），而不是摆一个光秃秃的 `¥0.00`。取表失败会在十分钟后重试，并且
    绝不覆盖已经可用的表。如果某个模型取不到，缓存就是
    `~/.cache/spend-watch/claude-pricing.json` 这个普通 JSON 文件，可以手工塞进去。
16. **托盘仅限 Windows。** 通知区域图标是 Windows 外壳对象，所以 `acm tray` 在别处不存在；它需要
    PowerShell 7 或 Windows PowerShell，而且它自己不读任何文件，所有数字都问守护进程——没有守护
    进程时它负责起一个。它由**任务计划程序**启动，因为 `acm` 直接生成的子进程会在命令退出时被杀
    掉（kill-on-close 的作业对象覆盖整个进程树），这正是图标闪一下就消失的原因。在任务栏自己的
    设置里它显示为 **Windows PowerShell**，因为图标属于真正持有它的进程，而不属于本项目。
17. **托盘显示的是上一个*已完成*的回合**，从来不是还在跑的那个；宿主没有记录回合边界时，会把
    数字标成基于调用跨度的较短估算。一个还在往上涨的合计，配上一个说它是最终值的标签，是它唯一
    绝不能做的事。
18. **通知区域图标是 16 个逻辑像素，没有更多。** 200% 缩放下系统把这个槽位画成 32 个物理像素
    ——托盘用的就是这个——但这是 Windows 给第三方应用的唯一文字槽位。任务栏自己那一行、时钟和
    电池百分比旁边的位置属于系统外壳：曾经允许第三方插入的 Deskband 接口已在 Windows 11 移除。
    剩下两条路是注入 `explorer.exe`，或者把窗口浮在任务栏上，都不值得那份脆弱。
19. **改托盘的脚本要重启托盘**——它是个正在跑的 PowerShell 进程，所以 `acm tray --stop` 之后再
    `acm tray`；而已经在跑的托盘持有会话级互斥量，会让之后每一次启动都安静地退出。如果启动看起来
    没反应，先看 `acm tray --status`。托盘自己的日志
    `~/.cache/agent-cost-monitor/tray.log` 记录了它走到哪一步，包括哪一次 DPI 感知调用成功、
    拿到多大的槽位。
